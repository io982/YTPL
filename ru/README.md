Скрипт на Python: скачивает аудио с видео YouTube и нарезает его на отдельные
треки.

**По умолчанию нарезка идёт по паузам в аудио, а главы и описание видео
игнорируются.** Причина: на миксах и сборниках авторские таймкоды обычно
размечают не треки, а крупные блоки. Например, у 108-минутного микса всего пять
глав «Sector I…V» — нарезка по ним дала бы пять файлов по 20 минут, в каждом
несколько треков. Метаданные берутся только принудительно, флагом
`--from-description`.

## Возможности

- Скачивание аудио с YouTube через yt-dlp
- **Нарезка по паузам между треками по умолчанию (`silencedetect`)**
- Рекурсивное понижение порога: старт с пауз 1.5 с и вниз до 0.8 с, пока
  остаются участки длиннее `--max-segment`; что осталось слишком длинным —
  режется ровно по этой длине
- Короткие огрызки сливаются с соседним треком (`--min-segment`)
- **Главы и таймкоды из описания — по запросу (`--from-description`)**:
  сначала главы YouTube, затем регэкспы по описанию, затем HTML-страница
- Ручные таймкоды (`--timestamps 145,325`)
- **Плейлисты**: по ссылке с `list=` предлагается скачать весь плейлист или
  только одно видео; каждый трек затем так же проверяется на паузы
- **Подробный лог-файл на каждый запуск** (`logs/ytpl-<дата>-<время>.log`) с
  выводом yt-dlp и traceback'ами
- Форматы меток: `&t=145s`, `?t=2m25s`, `=1102s` в URL, `MM:SS`, `HH:MM:SS`
- Нарезка на MP3 через ffmpeg, безопасные имена файлов
- Валидация меток (некорректные и перекрывающиеся пропускаются)
- Логирование, очистка временных файлов, проверка наличия ffmpeg
- Набор тестов на pytest

## Требования

- Python 3.8+
- yt-dlp
- requests
- beautifulsoup4
- imageio-ffmpeg (включает ffmpeg)
- Node.js — желательно: yt-dlp использует его для расшифровки ссылок YouTube,
  иначе загрузка упирается в троттлинг и таймауты
- yt-dlp-ejs — решатель JS-челленджа YouTube; без него загрузка падает с HTTP 403
- yt-dlp 2026.8.19 или новее — на 2026.07 все загрузки отвечали 403
- pytest — только для запуска тестов

## Установка

```bash
pip install -r requirements.txt
```

Node.js нужен дополнительно и пакетом Python не ставится: брать с
<https://nodejs.org>. Для тестов: `pip install -r requirements-dev.txt`.

## Использование

Интерактивно (спросит ссылку и режим; `Enter` — режим по умолчанию):

```bash
python YTPL.py
```

Или двойным щелчком по `YTPL.bat` (Windows).

Неинтерактивно:

```bash
python YTPL.py "https://www.youtube.com/watch?v=VIDEO_ID"
```

Если ссылка передана аргументом, скрипт работает в режиме по умолчанию без
вопросов.

### Параметры

| Параметр | Назначение |
| --- | --- |
| `-d`, `--from-description` | принудительно взять таймкоды из глав/описания вместо анализа пауз (псевдонимы: `--desc`, `--chapters`) |
| `-t`, `--timestamps 145,325` | свои точки реза в секундах |
| `--silence` | явно выбрать режим по умолчанию |
| `--playlist` | для ссылки с `list=` взять все треки без вопроса |
| `--no-playlist` | для ссылки с `list=` взять только указанное видео |
| `--overwrite` | скачать заново треки плейлиста, которые уже есть на диске |
| `--attempts 3` | попыток на трек, прежде чем он считается провалившимся |
| `--max-failures 5` | остановить прогон после столь многих неудач подряд; 0 — никогда |
| `--log-file PATH` | куда писать лог (по умолчанию `ytpl.log`) |
| `--no-log-file` | не писать лог-файл |
| `-v`, `--verbose` | отладочный вывод в консоль, включая собственный у yt-dlp |
| `--remote-components ejs:github` | разрешить yt-dlp скачать решатель JS-челленджа на ходу |
| `--noise 30dB` | порог громкости тишины (по умолчанию `-30dB`; минус можно опустить либо писать слитно: `--noise=-30dB`) |
| `--min-silence 1.5` | стартовый порог длины паузы, секунды |
| `--floor 0.8` | минимальный порог длины паузы, секунды |
| `--max-segment 300` | участок длиннее этого дорезается более низким порогом |
| `--min-segment 15` | минимальная длина трека; короткие куски сливаются с соседом |

Примеры:

```bash
python YTPL.py "https://youtu.be/VIDEO_ID" --from-description
python YTPL.py "https://youtu.be/VIDEO_ID" --min-segment 60 --max-segment 420
python YTPL.py "https://youtu.be/VIDEO_ID" -t 0,185,420,735
```

## Плейлисты

Ссылка с параметром `list=` указывает внутрь плейлиста. В этом случае YTPL
предлагает выбор:

```
This URL belongs to a playlist: "Essential NewRetroWave Vocal Jams" (426 tracks).
  [Enter] - download the whole playlist
  o       - only the video the URL points at
```

Ответить заранее можно флагами `--playlist` или `--no-playlist`. При
**неинтерактивном запуске берётся только одно видео**, если не передан
`--playlist`: несколько сотен треков не должны начинать качаться без присмотра.

**Перечисляется весь плейлист, а не та часть, которую показывает браузер.** На
веб-странице загружается около 200 записей, остальные подтягиваются при
прокрутке, но yt-dlp проходит эту пагинацию сам — плейлист на 429 записей
возвращается полностью за несколько секунд. Перечисление «плоское» (без
метаданных каждого видео), именно поэтому оно такое быстрое. Удалённые и
приватные записи приходят без названия: они подсчитываются и пропускаются.

Дальше каждый трек обрабатывается точно так же, как отдельное видео, то есть
паузы внутри него анализируются обычным образом. Всё складывается в одну папку,
названную по плейлисту:

```
Essential_NewRetroWave_Vocal_Jams/
  Sun_City_-_Restless_Heart_0001.mp3
  Thought_Beings_-_Sky_High_0001.mp3
  Thought_Beings_-_Sky_High_0002.mp3
```

Трек, который уже есть на диске, пропускается — остановленный прогон
продолжается с места остановки; `--overwrite` скачивает его заново. (Прежние
версии давали каждому треку свою подпапку; такие файлы при следующем запуске
поднимаются в папку плейлиста, так что ничего не скачивается дважды.)

На каждый трек даётся `--attempts` попыток, по умолчанию 3. Это не формальность:
YouTube на каждом извлечении выдаёт другой плеер-клиент, и часть из них отвечает
403 на ссылку медиа, поэтому вторая попытка того же трека обычно просто
срабатывает. Трек, провалившийся во всех попытках, прогон не останавливает —
но `--max-failures` неудач подряд останавливает: если загрузки перестали
работать, они такими и останутся, и прогонять через ту же ошибку ещё 400 треков
бессмысленно.

### Пока идёт прогон

В консоли одна строка состояния плюс строка на каждый готовый трек, а подробности
уходят в лог:

```
Playlist: Essential NewRetroWave Vocal Jams
426 tracks -> Essential_NewRetroWave_Vocal_Jams/
Keys: [p] pause   [s] stop after this track   [Ctrl+C] stop now

[1/426] Sun City - Restless Heart -> 1 file
[2/426] Thought Beings - Sky High -> 2 files
[3/426] 423 left | Subject Sue - Details in the Dark
```

| Клавиша | Действие |
| --- | --- |
| `p` | пауза после текущего трека, `p` снова — продолжить |
| `s` или `q` | остановить после текущего трека |
| `Ctrl+C` | остановить сейчас; текущий трек откатывается |

Клавиши, нажатые во время загрузки, срабатывают по её завершении — и это
намеренно: остановка на середине оставила бы недописанный трек. Файл с именем
`STOP` рядом с программой действует как `s` — на случай, когда до консоли не
добраться. В любом случае в сводке указано, на чём остановились, а повторный
запуск той же команды продолжает с этого места.

### Один файл на трек

Трек с достаточно длинной паузой внутри будет разрезан — для микса это как
правило и нужно, для песни не всегда. Чтобы каждый трек остался целым, задайте
минимальный сегмент длиннее любого трека:

```bash
python YTPL.py "<url>" --playlist --min-segment 600
```

## Логирование

Каждый запуск пишет свой файл лога, названный по моменту старта:

```
logs/ytpl-20261018-172847.log
```

То есть один файл — это одна сессия: ничего не дописывается в общий лог, и
файл, который нужно прочитать или отправить, — ровно тот запуск, который
только что был сделан. Флаг `--log-file` принимает другой путь и тоже
раскрывает шаблоны strftime (`--log-file "run-%Y%m%d.log"` даст один файл на
день); `--no-log-file` отключает запись в файл.

Консоль остаётся читаемой, а в файл идёт всё на уровне DEBUG:
ffmpeg), собственные сообщения yt-dlp, выбранный формат и полные traceback'и.
За строкой в консоли вида

```
ERROR - Download failed for https://...: HTTP Error 403: Forbidden
```

в файле лежит её полный traceback и весь обмен с yt-dlp, который к ней привёл.
Флаг `-v` дополнительно выводит отладочные строки в консоль и запрашивает
отладочный вывод у самого yt-dlp.

## Приоритет режимов

1. `--timestamps` — свои значения, важнее всего остального.
2. `--from-description` — главы → описание → HTML-страница. Если таймкодов там
   нет, выполняется переход на анализ пауз.
3. По умолчанию — анализ пауз; метаданные не читаются вообще.

## Результат

Файлы сохраняются в папку, названную по имени видео:
`{название_видео}/{название_видео}_{номер:04d}.mp3`

Например: `My_Video/My_Video_0001.mp3`, `My_Video/My_Video_0002.mp3`

## Тесты

```bash
pip install pytest
python -m pytest
```

Тестам не нужны сеть и YouTube: загрузка подменяется, а тестовое аудио
генерируется локально через ffmpeg. Покрыты разбор таймкодов, алгоритм анализа
пауз (разрывы, понижение порога, жёсткий рез, слияние огрызков), выбор режима и
реальная нарезка через ffmpeg.

## Если всё падает с HTTP 403

Это наблюдалось на практике: прогон плейлиста на 426 треков, где каждый трек
отвечал `HTTP Error 403: Forbidden`. Не хватало двух разных вещей, и исправить
нужно было обе.

**1. Решатель JS-челленджа.** YouTube требует решить свой `n challenge`, а для
этого нужны Node.js **и** скрипт решателя. Одного node недостаточно; без
скрипта в логе видно

```
n challenge solving failed: Some formats may be missing.
```

**2. Актуальный yt-dlp.** С установленным решателем предупреждение про челлендж
исчезло, но на yt-dlp 2026.07.04 403 остался. Тот же трек нормально скачался на
2026.08.19, поэтому в `requirements.txt` эта версия указана как минимальная.

Обе проблемы закрывает

```bash
pip install -r requirements.txt --upgrade
```

Наличие решателя проверяется при старте и отмечается в логе, а на каждый 403
выводится подсказка с тем, что установить — угадывать больше не придётся.
Вместо установки решателя можно разрешить yt-dlp скачать его на ходу:
`--remote-components ejs:github`. Это загрузка и выполнение кода из внешнего
источника во время работы, поэтому по умолчанию выключено.

## Обработка ошибок

- `--from-description`, но таймкодов в метаданных нет — переход на анализ пауз
- Точек реза не нашлось вовсе — аудио сохраняется одним файлом (при
  неинтерактивном запуске скрипт не зависает в ожидании ответа)
- Понятные сообщения при некорректных ссылках и отсутствующих зависимостях
- Валидация меток: некорректные и перекрывающиеся пропускаются
- Очистка временных файлов при выходе и при ошибке
- Проверка доступности ffmpeg до начала работы

## Изменения в последней версии

- **Поддержка плейлистов**: по ссылке с `list=` предлагается весь плейлист либо
  одно видео; перечисляется весь список (а не только ~200 записей, которые
  показывает браузер), недоступные записи пропускаются, готовые треки
  пропускаются при повторном запуске, сбой одного трека не останавливает прогон
- **Исправлено: ссылка с `list=` раньше ломала приложение** — yt-dlp возвращал
  плейлист вместо видео, а в таком ответе нет поля `duration`. Теперь при
  скачивании одного видео передаётся `noplaylist`
- **Логирование**: по одному подробному файлу лога на запуск в папке `logs/`,
  имя — по моменту старта сессии; баннер окружения, вывод yt-dlp в лог,
  traceback'и в файле и одна строка в консоли, флаги `--log-file` /
  `--no-log-file` / `-v`
- **Приветственный баннер** при запуске; в терминале уже 84 колонок вместо
  арта печатается обычная строка с названием
- **Отсутствие решателя JS-челленджа теперь сообщается** при старте и при
  каждом 403, а не оставляет сотни треков падать без объяснения;
  `--remote-components` разрешает скачиваемый решатель
- **Исправлено: зависший `node --version` мог повесить весь прогон.** Node
  проверяется один раз с таймаутом, и если он не отвечает, работа
  продолжается без JS-рантайма
- **Убран вопрос, когда резать нечего.** Трек без внутренних пауз — обычное
  дело для песни, аудио к этому моменту уже скачано, а сам вопрос ронял прогон
  при stdin в EOF (и задавался бы 426 раз на плейлисте)
- **Исправлено: каждая неудачная загрузка оставляла временную папку** — путь
  до неё вызывающая сторона не получала, и убирать её было некому. После одного
  упавшего прогона плейлиста таких папок осталось 134
- **`requirements.txt` / `requirements-dev.txt`** вместо строки с pip в README
- **Одна папка на плейлист**, а не на трек; файлы старой раскладки при следующем
  запуске поднимаются наверх, так что ничего не скачивается дважды
- **Тихая консоль**: строка состояния со всего/осталось/текущим треком, строка
  на каждый готовый трек, остальное — в лог
- **Пауза и остановка**: `p`, `s`/`q`, `Ctrl+C` или файл `STOP`, всё на границе
  трека; текущий трек откатывается, а в сводке сказано, с чего продолжать
- **Повторные попытки на трек** (`--attempts`): YouTube отвечает 403 на части
  своих же плеер-клиентов, и следующая попытка попадает на рабочий
- **Прогон, который перестал работать, теперь сдаётся** (`--max-failures`), а не
  прогоняет сотни треков через одну и ту же ошибку
- **Исправлено: ffmpeg печатал свой прогресс поверх вывода программы** при
  конвертации в mp3

- **Анализ пауз стал режимом по умолчанию; главы и описание используются только
  с флагом `--from-description`**
- **Интерфейс командной строки**: ссылку и режим можно передать аргументами,
  скрипт работает неинтерактивно; `YTPL.bat` прокидывает свои аргументы
- **Исправлено: аудио короче `--max-segment` (5 минут) не резалось вообще, даже
  при явных паузах между треками** — первый проход на стартовом пороге теперь
  выполняется всегда
- `--noise` принимает значение без минуса (иначе argparse читает `-30dB` как флаг)
- Набор тестов на pytest
- Кодовая страница UTF-8 в `YTPL.bat` — русские сообщения читаемы
